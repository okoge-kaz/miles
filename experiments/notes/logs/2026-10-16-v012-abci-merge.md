## 確認済みの機能境界

- ReplayDataBuffer は single-policy・Ray・fully-async の Megatron 学習用。
  upstream の multi-policy と Kubernetes hot restart は維持し、ReplayDataBuffer との併用は拒否する。
- submission / ready staleness は単一の policy clock を使うため single-policy 限定。
  multi-policy の生成 token version による既存計測は保持し、local clock による推測は行わない。
- HF export は `--hf-save-interval`、resume checkpoint は `--save-interval` で独立して制御する。
  HF のみの保存では prompt cursor / ReplayDataBuffer を保存しない。
  ReplayDataBuffer 保存前には model / optimizer の非同期保存を完了させる。
- policy lag は測定用に保持する。score centering も維持し、その loss でも policy lag を計測できる。
  score centering の有効化は既定値に追加せず、計測を有効にしても loss / 勾配は変えない。
- NeMo Gym Tau / Workplace は v0.1.2 の agent 子プロセス実行を維持する。
  episode 内のイベントを親へ返し、破棄した retry も含めて episode ごとに一度だけ計上する。
  応答収集が失敗した場合も agent の診断を aborted sample に保持する。
- Math 等の組み込み reward 用 Ray CPU worker は別機能として保持する。
  worker と loop 計測の生成・終了は rollout generation と同じ event loop で実行する。
- 評価の `reward=None` は平均から除外し、未採点数を記録する。
  pass@k も未採点を含む prompt group を除外し、除外数を記録する。
  v0.1.2 の未採点を0点として扱う方式より、外部採点器の障害と不正解を区別する ABCI 方針を優先する。
- SGLang の `begin_weight_update(weight_version=...)` は、現在の Miles からの利用はなくても
  互換 API として保持する。begin で受けた version は成功した end で公開する。
  現在の Miles は従来どおり end → 標準 `update_weight_version` → 生成再開の順で呼ぶ。
